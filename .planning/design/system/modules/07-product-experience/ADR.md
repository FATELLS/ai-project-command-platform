# ADR S-07：固定工作区、模板化语言与工作流优先体验

状态：`implemented baseline + accepted evolution`
关联：D-010–012、D-021、D-025–026、D-030–041、D-044–047

## Context

产品需要在保持 Xugu 迁移连续性的同时服务标准项目，并让复杂的材料、审核和版本边界对用户可理解。UI 不能成为第二套权限或数据模型，也不能只追求展示感。

## Decision

- 浏览器只使用仓库内固定语义 HTML/CSS/JavaScript renderer。
- 九模块按六个用户工作区组织。
- Xugu/标准项目语言由模板 presentation 驱动。
- 当前路由、深链和服务端 capability 是 UI 状态真相。
- 高频页面按当前任务和下一步组织视觉权重。
- 技术 ID、Schema 和内部状态默认不进入普通用户主界面。
- 项目资料只承载战果与材料；项目更新作为独立流程路由，只展示一张复用正式路线图 renderer 的更新模拟图。
- 移动端提供等价投影，不隐藏核心内容。

## Rejected Alternatives

| 方案 | 原因 |
|---|---|
| 项目提供前端组件 | 破坏固定渲染和安全边界。 |
| 深色通用 SaaS 侧栏 | 破坏既有产品连续性。 |
| 所有底层模块平铺 | 按技术实体而非用户任务组织。 |
| 只做视觉换肤 | 无法解决首屏和流程有效性问题。 |
| 为项目更新另建路线图 renderer | 重复正式路线图的布局、卡片与交互，必然产生视觉和行为漂移。 |

## Consequences

- UI 设计必须同时引用领域 capability 和用户流程。
- 新视觉规范不能改变发布/草稿语义。
- Phase 11 是本模块的目标演进规格，不是整个系统设计。

## Invariants

- UI 不自行授予权限。
- UI 不解析或执行项目/LLM 代码。
- 查看者只见发布态。
- 深链刷新可恢复同一业务对象。
