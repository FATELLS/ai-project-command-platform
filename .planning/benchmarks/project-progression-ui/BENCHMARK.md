# 项目推进材料 UI Benchmark

状态：`completed`

项目：`xugu-agentic-group`

## 目的

只通过产品 UI 验证非标准项目材料能否被安全摄入、形成可定位证据、显示材料 readiness，并在更新提案入口保持“AI 不直写草稿/发布态”的边界。禁止用后台 API 或直接数据库写入代替本 Benchmark。

## 用例矩阵

| ID | 材料 | 格式 | UI 更新模板 | 预期 |
|---|---|---|---|---|
| BM-01 | 项目推进模拟周会纪要 | DOCX | 会议纪要 | 上传成功；状态进入证据已就绪；行动项、负责人、日期、风险和成果可在详情中定位 |
| BM-02 | 跨单元推进台账 | XLSX | 进度汇报 | 上传成功；工作表/单元格定位可见；缺负责人/日期和冲突备注不被补造 |
| BM-03 | 项目群聊记录 | TXT | 会议纪要 | 上传成功；非结构化对话形成证据；60% 与“八成”的冲突均保留 |
| BM-04 | 邮件转发链 | TXT | 进度汇报 | 上传成功；邮件头、转发层级、风险与下一步行动可读 |
| BM-05 | 供应商状态回执 | JSON | 进度汇报 | 上传成功；JSON 指针或结构化定位可见；外部回执仍只是证据 |
| BM-06 | 邮件原件 | EML | 进度汇报 | UI 明确拒绝不支持格式；材料台账不新增记录 |
| BM-07 | 重复上传 BM-01 | DOCX | 会议纪要 | UI 显示“相同内容已归档”；材料台账不出现重复材料 |
| BM-08 | LLM 路线生成项目计划 | UI 人工材料（TXT 内容） | 项目计划 | 授权后由真实 provider 只生成 3 个带证据的 roadmap 新增项；逐项人工审核、事务合并、受控发布后在项目路线图验收 |

## UI 操作约束

1. 从“项目资料 → 材料台账”进入。
2. 每个正向用例均使用“上传作战材料”，选择对应文件、材料分类和更新模板后提交。
3. 只通过页面状态、台账行、材料详情和证据预览判断结果。
4. 负向用例必须从同一上传界面操作，不直接调用材料 API。
5. 可进入“更新提案”查看生成准入；若 provider 未启用，应诚实显示禁用状态，不得伪造成功提案。
6. BM-08 的授权、生成、逐项审核、草稿合并、发布和路线图验收必须全部从 UI 完成；不得用后台 API 或数据库代替任一步骤。
7. LLM 只能生成 `ChangeProposal`；只有人工审核、事务合并和人工发布才可依次改变 `draft` 与 `published`。

## 通过标准

- 五个正向材料均在 UI 台账出现，文件名、格式、模板、状态、证据块数量和上传时间可读。
- 至少分别打开 DOCX、XLSX、TXT、JSON 材料详情，证据定位与预览不串材料。
- 不支持 EML 和重复 DOCX 均有明确 UI 反馈，且不产生额外台账记录。
- 项目路线图、项目健康和项目资料导航仍可正常进入，页面无布局破裂或横向溢出异常。
- UI 中所有推进建议仍停留在材料/提案层，未审核前发布态项目路线图不改变。
- BM-08 恰好生成 3 个 roadmap create 项，字段与证据匹配材料约束；人工发布后版本递增，三个节点在路线图折叠态和展开态均正常显示。
