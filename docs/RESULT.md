# 当前结果

> 本文件只描述已经完成并通过验证的结果。规划目标见 `.planning/`。

## 已完成

- 建立独立项目、需求、架构、路线图、AI 契约和只读迁移基线。
- 建立 Node.js 24.15+ 与内置 SQLite 数据底座，包含迁移校验和、WAL、外键、索引和事务。
- 项目、模板、用户、成员、版本、模块、作战单元、路线、闭环、任务、依赖、战线和提案元数据使用独立实体。
- `published` 与 `draft` 使用独立版本图；项目指针受归属和层级约束。
- `xugu-agentic-group` 脱敏 v4.2 已迁移，保留 7 个作战单元、29 项任务、6 个节点、2 个闭环和 4 条公司战线，导出与夹具语义等价。
- 密码使用带盐 scrypt；会话 token 只以 SHA-256 摘要保存，浏览器使用 HttpOnly、SameSite=Strict Cookie。
- 会话有 30 分钟空闲与 8 小时绝对过期，写操作使用内存 CSRF token，登录有统一错误与 IP 窗口限流。
- 建立平台管理员、项目管理员、项目编辑者、查看者角色；项目列表和详情按 `projectId` 与成员权限隔离。
- 建立授权项目搜索、状态筛选、排序、最近访问前四、项目切换和只读发布态概览。
- 平台管理员可事务性创建、编辑、归档和恢复项目；每次生命周期变化写入追加式审计事件。
- 创建项目生成相互独立的空发布版/草稿版，并授予创建者项目管理员角色；不写虚构完成率。
- 提供本地语义 HTML/CSS/JavaScript 平台 UI，含登录、项目首页、项目壳和可访问管理对话框；桌面端已按 Xugu 稳定界面修正为 76px 白色顶部导航、暖色指挥背景、左右双栏 Hero 和横向章节卡片，无深色 SaaS 侧栏。
- 项目详情的顶部标题、Banner、当前状态提示、事实标签、模块标签和新建摘要已由项目模板/术语配置驱动；`xugu-agentic-group` 作为首个 Xugu Agentic Group Schedule 作战项目保留作战语言，标准项目使用团队、任务、里程碑和交付物语言。
- 提供不可变、版本化的 `campaign-map-v1@1.0.0` 与 `standard-project-v1@1.0.0` 目录；模板定义受控主题、术语、字段、状态、必需模块、顺序、Schema 和默认视图。
- 服务端注册 Overview、Units、Roadmap、Task Network、Gantt、Outcomes、Risks、Metrics、Materials 九种模块；未知类型、Schema、视图、关系和可执行资产失败关闭。
- 浏览器通过仓库内固定 DOM/SVG renderer map 展示九类模块；项目配置不能提供 HTML、CSS、JavaScript、SVG 或组件路径。
- 模块配置采用完整列表事务，只写 `draft`；Overview 固定启用，保存草稿不改变 `published` 导航或删除事实，查看者无配置入口。
- Xugu Roadmap/Task Network/Gantt/Outcomes 保留 6 阶段、2 闭环、4 战线、29 任务和 28 有日期/1 待排期语义；标准夹具独立显示 3 团队、7 任务、4 里程碑、2 工作流及线性/依赖列表/泳道变体。
- Xugu 战役路线图使用固定可配置 renderer 呈现曲线路线；主图只显示战役节点，并在当前节点上直接显示可点击的作战单元分支胶囊和任务数。节点可点击并深链到 `?stage=...`，分支胶囊可深链到 `?stage=...&unit=...` 并将对应分支详情高亮置顶；下方节点详情显示说明、预期产出、本地预览资源，以及按作战单元和任务日期推断出的分支任务；分支任务会在原位展开详情并深链到 `?stage=...&task=...`。
- 作战单元模块点击“查看作战单元详情”后在当前卡片内展开该单元路线、战役节点和支线任务；点击单元支线任务同样在原位展示任务详情，不再把结果隐藏到页面底部。
- Materials 模块已成为固定项目材料工作区，提供服务器权威配额、流式文件上传、人工材料、持久台账、状态筛选、处理重试、更新意图和独立问答授权。
- 摄入层校验文件大小、魔数/MIME、压缩路径与展开上限、容量、频率和并发；可选扫描器配置为必需时不可用即失败关闭，失败流不会留下孤儿对象。
- 证据处理支持人工文本、TXT、JSON、CSV、DOCX、PPTX、XLSX，以及受限 PDF/图片子进程适配器；证据保留段、页、幻灯片、单元格、边界框或 OCR 定位和稳定摘要。
- 项目问答使用同一 SQLite 事务域内的项目/授权/当前代际过滤与 FTS5 检索；provider 默认禁用，证据视为不可信文本，输出只接受 allowlist 引用，无证据或 provider 不可用时诚实拒绝。
- Chat 与未来 Generation 使用独立持久配额和全局有界 provider 并发；Phase 4 问答只读，不写 proposal、draft 或 published。
- 六类更新模板以不可变 `id@version` 目录约束会议纪要、项目计划、进度汇报、指标数据、成果归档和新项目材料可生成的模块、操作、字段与高影响证据要求。
- 生成任务锁定当前项目发布版本、同模板材料、当前提取代际、证据 ID/哈希和 Schema；支持幂等创建、失败重试 lineage、stale 基准、attempt、Token 和版本化成本记录。
- generation 使用独立服务端 provider 配置、4 次/分钟与 100 次/日预算，并与 chat 分账；无配置时材料和既有提案仍可浏览，提交明确禁用。
- `change-proposal-v1@1.0.0` 只接受有界结构化增量；服务端重新校验 envelope、项目/证据归属、模板字段、目标、语义、日期、依赖 DAG、重复与版本冲突，非法输出最多修复一次后失败关闭。
- 仅完整验证通过的提案、变更项和证据关系在一个事务中保存；所有生成成功、失败和重试路径均无权修改 `draft`、`published` 或项目版本指针。
- 固定 Materials renderer 提供 Xugu“作战更新提案”和标准“项目更新提案”工作区、任务详情、验证结果、字段差异、置信度/警告与精确证据回跳。
- 审核决定与提案项分离保存；管理员可逐项接受、驳回、字段绑定编辑后接受或整模块接受，编辑值会重新执行 Schema、证据、日期、任务归属和依赖校验。
- 接受项使用 copy-on-write 新草稿版本事务合并；版本复制、字段应用、关系约束、完整图校验、校验和和草稿指针切换同成同败，AI 无合并权限。
- 发布中心确定性比较当前 `published` 与 `draft`，显示按模块差异、结构检查、未决审核和直达发布禁令；人工确认后创建新发布版本及独立草稿基线。
- 回滚只接受当前发布事件的直接前驱，回滚后建立新草稿基线；审核、合并、发布、回滚、用户和成员动作进入追加式审计。
- 平台管理员可通过项目隔离 API 创建/停用用户并管理成员角色；项目管理员可管理本项目编辑者/查看者，最后一个平台/项目管理员受保护。
- 提供一致 SQLite `VACUUM INTO` 备份、完整性/外键/迁移校验和离线恢复前自动备份；项目导入支持显式模板且导出不包含密钥或运行材料。
- 材料关键内容覆盖按六类更新模板给出 `ready / warning / blocked` 诊断；材料台账、材料详情、生成准入和生成上下文都会显示或保存关键缺失、建议补充项与诊断建议。
- 生成任务在锁定材料时保存 readiness 快照；关键内容缺失会在调用 provider 前以 `MATERIAL_READINESS_BLOCKED` 阻止生成，避免用缺字段材料更新项目。
- 作战单元支持 `active`、`archived`、`exited` 生命周期；新增、归档和退出只能通过带证据的结构化提案进入审核，删除作战单元被拒绝。
- 归档或退出作战单元必须提供生效日期、原因和证据；若仍有未关闭任务，必须在同一提案中关闭、完成或归档相关任务，否则合并前校验失败。
- 所有 HTTP 响应带 `x-request-id`；未知 5xx 会写入脱敏错误事件，保存 request/trace、路由、用户、项目、状态、错误指纹、堆栈和关联上下文。
- 平台管理员和授权项目管理员可在 Materials 工作区“运维自检”中运行核心产品测试，查看测试运行、最近错误和可复制诊断包；查看者无法访问。
- Phase 6 参考集覆盖 10 个 grounding、隔离、版本、图、日期、重复、审核、事务和发布场景；非法任务归属在审核编辑保存时失败关闭。
- 直接刷新项目路由、会话过期、退出后 Back、未知/越权统一 404 已通过真实浏览器验证。
- 统一验证通过 148 项自动化测试，以及 Phase 3–6 共 63 个浏览器阻断用例、Phase 7–8 共 26 个 Playwright 全自动浏览器 E2E；19 张证据均通过 SHA-256 与尺寸机检。
- Phase 7 本机浏览器抽查确认虚谷项目 Materials 模块、运维自检入口和 `5/5` 核心自检运行可用。
- 验证确认参考 Xugu 应用的 HEAD、Git 状态和脱敏种子哈希未变。

- Roadmap 模块升级为五种受控视图，通过同一路由的 `?view=` 切换：活动路线图（战略曲线 SVG + 按 stage 的时间列，含目标与归入该窗口的分支任务）、项目泳道（主泳道按时间轴铺阶段、副泳道按作战单元铺任务条，双锚点 + 并行子任务）、阶段卡片板（任务按 待确认/进行中/待审核/已完成 状态泳道）、作战单元进度（单元卡显示完成度，点击/键盘展开任务）、依赖网络（复用 task-network 数据、可按单元筛选）。五种视图共享同一版本化项目图投影（`loadRoadmap` 输出 units/tasks/edges），切换不改变 published/draft/proposal 边界。
- 项目泳道（`?view=swimlane`）以分形生命周期（事前/事中/事后，由 `stage.state` 派生）为顶带：主泳道沿任务时间轴铺排阶段（阶段起点即拆解锚点·项目锚点），副泳道为各作战单元的甘特任务条（同单元并行子任务按 track 着色、`?unit=` 高亮、`?task=` 就地下钻），收口锚点由 `closures.between` 两端阶段中点生成并可 `?anchor=` 深链；`?stage=` 选中时跨泳道淡化非该阶段任务。该视图纯投影渲染，不改隔离与数据边界。
- 阶段卡片板任务卡可拖拽（仅编辑者及以上），拖拽只创建 `interaction` 模板 ChangeProposal，绝不直写 draft/published；高影响字段（state/owner/日期）必须引用本项目已就绪材料证据，经审核与 copy-on-write 草稿合并后才生效。
- 新增交互提案服务路径 `createInteractionProposal`：锁定当前 published、复用 validator、保存为 pending，不调用 LLM、不创建 generation job；缺 CSRF 返回 403，viewer 返回统一 404，伪造/跨项目证据返回 EVIDENCE_NOT_ALLOWED。
- 审核工作区把每项 proposal item 呈现为审核卡片（字段差异、证据定位、置信度、警告、接受/驳回/编辑后接受），整模块接受与事务合并沿用 Phase 6 边界。
- 路线节点、分支、作战单元、任务和审核卡片均有可见可点击性、键盘访问、选中态、就地详情和可复制深链（`?view=`/`?stage=`/`?unit=`/`?task=` 正交）。
