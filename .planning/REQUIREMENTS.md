# 需求清单

状态：`accepted`

## 平台与项目

- **PLAT-01** 登录后可以查看、搜索和切换授权项目。
- **PLAT-02** 平台管理员可以创建、编辑、归档和恢复项目。
- **PLAT-03** 每个项目拥有稳定 ID、名称、模板、主题、术语、状态和独立版本。
- **PLAT-04** 每个项目可以包含多个作战单元或团队。
- **PLAT-05** 当前虚谷作战地图必须迁移为 `xugu-agentic-group` 首个项目。

## 模块与模板

- **MOD-01** 提供项目概览、作战单元、路线、任务网络、甘特、成果、风险、指标和材料九类基础模块。
- **MOD-02** 固定模块由受控前端组件渲染，不执行项目材料或 LLM 生成的代码。
- **MOD-03** 九类基础模块在产品导航中按用户任务收敛为六个一级工作区：总览、项目路线图、作战单元/团队、排期甘特、项目健康和项目资料；模块注册、权限与版本边界不因导航分组改变。
- **MOD-04** 任务依赖作为项目路线图的辅助投影，不重复占用一级入口；风险与指标归入项目健康，成果与材料台账归入项目资料，并提供可键盘访问的二级导航。项目更新是独立流程动作，不作为项目资料的子分区或第七个内容模块。
- **TPL-01** 模板定义术语、必填模块、字段、状态、校验、默认视图和主题。
- **TPL-02** 首版提供 `campaign-map-v1` 作战地图模板。
- **TPL-03** 首版提供普通项目管理话术的标准项目模板。

## 路线图可视化与卡片工作台

- **VIS-01** 路线模块以卡片泳道作为项目路线图主视图，并提供阶段卡片板、作战单元进度和依赖网络三个辅助投影；视图切换不得改变 `published / draft / proposal` 的数据边界。
- **VIS-02** 项目路线图以主任务/阶段为时间锚点，按作战单元展开固定宽度副任务卡片；不得再用独立装饰性曲线重复表达同一路线，也不得用副任务卡宽度伪装甘特工期。
- **VIS-03** 任何路线节点、作战单元、分支任务或卡片的选择都必须有明确选中态、就地详情和可复制的深链；用户不应依靠长距离滚动才能发现点击结果。
- **VIS-04** 阶段卡片板按状态泳道展示任务、负责人、日期、证据数量和关键缺失；拖拽或状态移动只能创建受角色与证据约束的 `ChangeProposal`，不得直接改写 `draft` 或 `published`。
- **VIS-05** 多作战单元、多任务和跨阶段依赖必须可在项目路线图、卡片板和依赖网络之间交叉定位；不同视图只是同一受控数据的不同投影。

## 材料与证据

- **MAT-01** 每份材料必须归属一个项目。
- **MAT-02** 支持纪要、DOCX、PPTX、XLSX、PDF、文本、图片和人工表单。
- **MAT-03** 材料提取后形成可定位的证据块，保留来源文件、页/段/表位置和摘要。
- **MAT-04** 上传门阀包含容量、类型、签名、重复摘要、频率、并发和解包限制。
- **MAT-05** 原件、预处理文本、问答授权和项目发布状态保持分离。
- **MAT-06** 所有接收项目更新材料的 UI 入口必须提供统一、版本一致的材料模板下载；空文件、伪装类型、未知格式、重复材料或与所选用途不匹配的材料必须原位给出可行动错误，且不得留下孤儿材料、生成任务或部分更新。

## AI 低代码更新

- **AIU-01** 管理员选择材料和更新模板后可以创建生成任务。
- **AIU-02** LLM 只能输出符合版本化 Schema 的 `ChangeProposal`。
- **AIU-03** 每项事实、完成状态和指标值必须携带证据引用。
- **AIU-04** 每项变化标注 `fact`、`plan`、`suggestion` 或 `unknown`。
- **AIU-05** 默认生成相对当前发布版本的增量，不整项目重写。
- **AIU-06** 服务端校验项目归属、Schema、任务依赖、日期、证据、重复和版本冲突。
- **AIU-07** AI 不得直接写入 `draft` 或 `published`，不得生成并执行代码。
- **AIU-08** 生成前必须给出材料关键内容覆盖诊断；缺失会影响高影响字段或作战单元生命周期时标记为关键缺失并阻止或降级生成。
- **AIU-09** 作战单元或团队的新增、归档、退出只能作为带证据的版本化提案进入审核，不得物理删除历史事实。

## 作战单元生命周期

- **UNIT-01** 作战单元支持 `active`、`archived`、`exited` 生命周期状态，保留生效日期、原因、证据和操作人。
- **UNIT-02** 归档或退出作战单元前必须检查未完成任务、依赖、甘特泳道和战线引用；未同步关闭、迁移或归档的引用必须阻止合并。
- **UNIT-03** 已归档或退出的作战单元仍可在历史发布版本中查看，在当前发布版中默认折叠或标记，不从审计和证据链中消失。

## 作战生命周期与拆解模型

- **LIF-01** 路线图必须以通用生命周期范式（事前/事中/事后）作为顶层分带，由阶段状态派生；范式名称可随项目模板配置（如 PDCA 或客户自定义术语），不硬编码单一表述。
- **LIF-02** 路线图必须区分主泳道（阶段时间轴）与作战单元副泳道（甘特任务条）；副泳道可表达同一作战单元同一时间并行多个子任务，并能按 `?unit=`/`?task=` 深链定位。
- **LIF-03** 主泳道阶段起点必须显式标记为"拆解锚点"（主→副任务拆解起点）；副泳道任务汇入主泳道的收口必须显式标记为"收口锚点"，二者均可深链与追溯。
- **LIF-04** 一个阶段支持多次向下拆解（一个阶段可多次分发子任务到不同作战单元）与多源合并收口（多个子任务/单元汇入同一收口锚点）；拆解与收口关系可追溯到证据与版本，变更必须经结构化提案审核，不直写 draft/published。
- **LIF-05** 生命周期范式分形下沉：作战单元副泳道内部可表达自己的事前/事中/事后阶段动作，而非只有项目级生命周期带。

## 审核与发布

- **REV-01** 管理员可以按模块查看新增、修改、删除差异。
- **REV-02** 每项差异显示原值、建议值、证据、语义类型、置信度和警告。
- **REV-03** 支持单项接受、驳回、编辑和整模块接受。
- **REV-04** 接受的变更通过事务合并到 `draft`，失败时不产生部分写入。
- **REV-05** 发布前提供项目预览和检查清单，发布后可回滚到上一版本。
- **REV-06** 材料上传或生成完成后，审核工作区必须把每项新增、更新、归档建议呈现为可审阅卡片，显示字段差异、证据、关键缺失、风险和“接受 / 编辑后接受 / 驳回”动作；卡片操作仍复用既有审核、草稿合并和发布边界。
- **REV-07** 普通 UI 将结构化变更统一表达为“AI 生成项目节点预览”；预览卡片下方必须用当前发布图加待决定/已接受变更生成只读路线图投影，突出新增、修改和选中节点，已驳回项退出投影，且预览过程不得写入 `draft` 或 `published`。
- **REV-08** 路线图主节点和任务卡片必须提供受控编辑与删除入口：正式路线图操作创建人工 `ChangeProposal` 并进入审核，AI 节点预览只允许修改或移除当前 proposal 中由本次材料生成的 change item；删除必须输入“确认删除”，正式路线图的高影响编辑和删除还必须引用当前项目证据。

## 权限与审计

- **AUTH-01** 首版包含平台管理员、项目管理员、项目编辑和只读访问者。
- **AUTH-02** 用户只能访问授权项目。
- **AUTH-03** 登录、材料、生成、审核、发布、回滚和删除操作进入审计日志。
- **AUTH-04** AI 配置密钥只保存在服务端，不返回浏览器或日志。
- **AUTH-05** 生产错误、请求追踪、诊断包和测试运行记录只能由平台管理员或授权项目管理员查看，并必须脱敏 Cookie、CSRF、密钥、材料正文和模型提示词。

## AI 问答

- **CHAT-01** 问答必须携带 `projectId`，只读取该项目已发布状态和授权材料。
- **CHAT-02** 回答引用来源，资料缺失时明确说明，不补造进度。
- **CHAT-03** 项目问答与项目更新生成使用独立权限和调用配额。

## 数据与非功能

- **DATA-01** 首版使用 SQLite，提供迁移、事务、索引和备份恢复。
- **DATA-02** 项目、材料、提案、版本、用户和审计均使用独立实体，不塞进单一 JSON。
- **NFR-01** 单服务器首版支持本机或局域网部署。
- **NFR-02** 所有高影响变化和跨项目越权均有确定性测试。
- **NFR-03** 生成失败不影响已有项目浏览和编辑。
- **NFR-04** 项目模板和 Schema 必须版本化并可迁移。
- **NFR-05** 每个 HTTP 请求、后台材料任务、生成任务、审核合并和发布动作都有稳定 `requestId` 或 `traceId`，错误响应返回可报障编号。
- **NFR-06** 未知异常必须记录可检索的脱敏堆栈、错误指纹、用户/项目/路由/版本上下文和相关作业 ID。
- **NFR-07** 产品内提供管理员可运行的自检与回归用例中心，覆盖材料更新、关键缺失、作战单元生命周期、权限、发布和可观测性。
- **NFR-08** 源码部署必须提供后台启动、状态查询、优雅停止和重启入口；停止平台时只终止平台进程并释放自身 worker/连接，不得隐式停止外部数据库或其他依赖服务。

## 首版暂不包含

- 多服务器分布式部署；
- 实时多人协同编辑；
- 任意自定义代码模块；
- 无审核自动发布；
- 对外开放的公共注册。

## 用户体验简化（Phase 10 方向）

### 项目创建

- **CRT-01** 项目创建支持三种入口：对话式、上传材料自动解析、手动表单。
- **CRT-02** 对话式创建通过 AI 引导逐步收集项目信息（名称、目标、团队、里程碑等），对话结束后生成项目骨架供确认。
- **CRT-03** 上传材料创建允许用户直接上传项目启动会会议纪要等材料，系统自动提取项目信息并生成路线、团队、任务骨架供确认。
- **CRT-04** 手动表单创建保留当前方式（ID、名称、模板），不受影响。
- **CRT-05** 无论哪种创建方式，最终都生成标准项目实体和模板配置，不绕过权限和数据隔离。
- **CRT-06** 上传材料创建必须提供项目创建模板，并复用材料入口的空文件、声明类型与内容签名校验；文本材料缺少明确项目名称或项目目标时不得进入骨架确认。

### 材料到更新的流程简化

- **SIM-01** 材料处理完成后无需手动授权即可生成更新建议；界面不再出现"问答授权""生成授权"概念。
- **SIM-02** 生成更新建议后直接展示为卡片预览（新增卡片、修改卡片），用户确认即发布；删除卡片仍需手动操作。
- **SIM-03** 底层安全边界不变：AI 仍不能直接写 draft/published；确认发布仍由人工触发。
- **SIM-04** 生成流程从"选材料、开面板、选模板、生成"简化为"一键生成、看卡片预览、确认发布"。

### 战情问答入口

- **CHAT-04** 战情问答从材料工作区内部标签移出，改为项目页面右侧独立浮动按钮，类似咨询入口。
- **CHAT-05** 浮动问答面板在所有项目页面可用，不占用一级导航或材料工作区标签。

### 材料页面冗余消除

- **UX-01** 项目资料页面的二级导航与材料工作区内部标签不重复出现相同层级入口；进入"项目材料"后不再多一行重复标签。

## 工作流优先 UI（Phase 11）

- **WUI-01** 项目级一级导航恰好为六个工作区；同一页面只出现一个 H1 和一组本地导航。
- **WUI-02** 在 1280×720 下，每个主要页面的核心对象和一个主操作位于首屏。
- **WUI-03** 查看者不看到草稿、提案、审核统计、发布操作、运维信息或内部技术 ID。
- **WUI-04** 项目列表首屏先显示搜索、关注项目和最近项目，不使用占据首屏的大型营销 Hero。
- **WUI-05** 项目总览首屏按“需要处理、当前进展、近期变化”排序，项目介绍置于其后。
- **WUI-06** 三种项目创建方式都必须在最终创建前显示可编辑的项目骨架确认。
- **WUI-07** 材料空状态和常规状态的上传入口都位于首屏；配额与实现说明不先于上传任务。
- **WUI-08** 材料状态以用户可行动的状态机呈现；失败或缺失状态必须给出下一步操作。
- **WUI-09** 更新建议详情先显示业务对象、变化、原因、影响和证据；UUID、Schema 和字段路径默认折叠。
- **WUI-10** 新增项不显示空原值栏；修改项显示语义化前后对比；高影响变化必须逐项确认。
- **WUI-11** “确认并发布”只编排现有审核、合并、检查和发布边界；任一步失败都不得越过发布前状态。
- **WUI-12** 移动端不得删除核心图表或工作内容，必须提供等价列表、分页或可滚动画布。
- **WUI-13** 项目问答在所有项目工作区可访问，但不得遮挡主要操作，并继续只读且带来源。
- **WUI-14** 平台设置默认只展示必填配置、连接状态和测试连接；高级参数折叠。
- **WUI-15** 关键文本满足 WCAG AA；正文不小于 14px，元数据不小于 12px，移动端点击目标不小于 44×44px。
- **WUI-16** 所有弹窗和侧栏支持焦点陷阱、Esc 关闭、关闭后焦点恢复和明确可访问名称。
- **WUI-17** 模板术语、固定 renderer、项目隔离、CSRF、审计、版本和深链边界不回退。
- **WUI-18** 390×844、1280×720、1440×900 三组视口纳入浏览器与视觉回归验收。
- **WUI-19** 项目创建和项目更新链路中每个材料输入或发起更新的入口都提供就近模板下载，模板选择使用统一目录且下载不改变当前页面状态。
- **WUI-20** 创建、更新和阶段生成的异常材料必须在当前弹窗或面板显示原因与下一步；失败后项目数、材料数、生成任务和已发布状态保持不变。
- **WUI-21** “项目更新”使用独立流程路由，不归入项目资料二级导航；项目资料负责长期材料台账，通用项目更新入口负责从本次材料开始一次更新。
- **WUI-22** 正式路线图与 AI 节点预览共用节点卡片编辑器，支持查看、增加、修改和清除允许字段；每张可编辑卡片有明确“编辑”按钮和强确认删除。AI 预览中仅本次生成的新增/修改卡片提亮可编辑，当前发布图的上下文卡片降亮并标为只读。
- **WUI-23** 某次更新进入预览阶段后只渲染一张“更新后的项目路线图”，不得同时显示生成统计、提案列表、生成任务列表和另一套路线图；该路线图必须直接复用正式项目路线图 renderer，仅以受控模式参数区分本次可编辑卡片和只读发布节点。
- **WUI-24** 熟悉的工具和卡片操作采用同一套线性图标；图标按钮必须有可访问名称与 tooltip，操作位必须位于对象边界内且不遮挡内容。编辑使用铅笔图标而非可见“编辑”文字，删除、发布等高风险动作仍使用明确文字。
- **WUI-25** 所有通用“项目更新”入口必须先进入本次更新材料步骤，再依次进入处理/生成、模拟路线图、人工审核和发布；不得默认打开最近一次预览。生成完成后的继续入口必须携带具体 `proposalId`，历史未完成更新只能作为次要“继续处理”入口。
