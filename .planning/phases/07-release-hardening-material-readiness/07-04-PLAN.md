# Plan 07-04：产品内自检与回归用例中心

1. Define a versioned product test catalog for safe, deterministic checks:
   - material readiness and critical missing cases;
   - material to proposal to review to draft merge;
   - unit create/archive/exit lifecycle;
   - cross-project authorization;
   - release preview/publish/rollback dry-run checks;
   - observability requestId/error-event capture.
2. Add a test-run service that executes selected cases against an isolated temporary project or rollback-only transaction, never mutating the current published version.
3. Persist test runs, case results, timings, failure requestIds and artifact pointers.
4. Add an admin UI under the release/operations area to run core smoke tests, view latest results and export a support report.
5. Integrate the same catalog into `npm run verify` so product self-tests and CI tests stay aligned.
6. Add browser UAT for the test center empty state, successful run, failed synthetic case and unauthorized access.

## Verification

- `npm run verify`
- Browser UAT: platform admin runs the core suite and sees case-level results; project viewer cannot access the test center.
