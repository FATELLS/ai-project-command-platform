## 1. 全局导航结构

平台的 UI 分为三层导航，理解这三层是理解整个操作流程的钥匙：

```
┌─────────────────────────────────────────────────────┐
│  顶部全局栏（appFrame, app.js:233）                    │
│  [品牌] AI PROJECT COMMAND   [项目切换器▾] [退出]     │
├─────────────────────────────────────────────────────┤
│  模块导航栏（moduleNavigation, app.js:565）            │
│  总览 | 路线图 | 作战单元 | 甘特 | 健康度 | 项目资料    │
├─────────────────────────────────────────────────────┤
│  子分区导航（moduleSectionNavigation, app.js:603）     │
│  战果档案 | 项目材料 | 更新建议 | 审核发布 | 运维自检   │  ← 仅"项目资料"组显示
├─────────────────────────────────────────────────────┤
│                                                       │
│                   模块内容区                           │
│                                                       │
└─────────────────────────────────────────────────────┘
```

- **顶部全局栏**：始终存在（登录页除外），含品牌链接、项目切换器下拉、退出按钮
- **模块导航栏**：项目详情页内显示，按分组排列模块入口
- **子分区导航**：当进入"项目健康"或"项目资料"分组时显示二级 Tab

## 2. 登录与初始化

**代码**：`renderLogin()` — `app.js:165`

### 登录页布局

左右分栏：
- **左侧品牌区**（`.login-brand`）：产品标语"让每个项目都有清晰的作战现场"，信任列表（项目级数据隔离 / 变更可追踪 / 发布由人审核）
- **右侧表单区**（`.login-form-panel`）：账号输入框 + 密码输入框 + 登录按钮

```
┌──────────────────┬──────────────────┐
│                  │  欢迎回来         │
│   AI             │  登录项目作战平台  │
│  PROJECT         │                  │
│  COMMAND         │  账号: [______]   │
│                  │  密码: [______]   │
│  让每个项目都有   │                  │
│  清晰的作战现场   │  [登录平台]       │
│                  │                  │
│  ✓ 项目级隔离    │  默认 admin/123   │
│  ✓ 变更可追踪    │                  │
│  ✓ 发布由人控制   │                  │
└──────────────────┴──────────────────┘
```

### 操作流程

1. 输入账号密码 → 点「登录平台」
2. 登录成功 → 自动跳转到 `state.intendedPath`（之前尝试访问的页面）或 `/projects`
3. 登录失败 → 表单下方显示红色错误提示，密码框清空
4. **首次登录** → 如果 `session.mustResetPassword === true`，强制跳转到 `/account/password` 修改密码页（`app.js:1619`）

### 关键细节

- 默认账号 `admin / admin123`，页面底部有文字提示
- 密码输入框 `autocomplete="current-password"`
- 提交时按钮变灰显示"正在登录…"，防止重复提交

## 6. 路线图模块

**代码**：`renderRoadmap()` — `renderers.js:225`
**路由**：`/projects/:id/modules/roadmap`

路线图有 3 个子视图，通过视图切换器（`roadmapViewSwitcher`）切换：

| 视图 | query 参数 | 说明 |
|------|-----------|------|
| **项目路线图**（默认） | 无 `view` 参数 | 阶段卡片板：按任务状态泳道排列，卡片可拖拽 |
| 作战单元进度 | `?view=units` | 以作战单元为入口，展示覆盖阶段、任务、完成度 |
| 依赖网络 | `?view=network` | 跨单元跨阶段阻塞关系图 |

### 路线图主视图（泳道）

- 按阶段（Stage）垂直排列
- 每个阶段是一个卡片板区域
- 任务卡片含：标题、负责人、状态色点（on-track 绿 / at-risk 橙 / off-track 红）
- **拖拽任务卡片**可发起状态变更提案（受控流程，不直写数据）

### 作战单元进度视图

- 卡片网格，每张卡片代表一个作战单元
- 显示：单元名称、目标、负责人、任务数、进度条
- 点击卡片 → 展开该单元的任务列表

## 9. 材料详情页与 5 步引导器

**代码**：`renderMaterialDetail()` — `renderers.js:1651`
**路由**：`/projects/:id/modules/materials/:materialId`

这是单个材料的处理中心，核心 UI 是 **5 步引导器**（`materialStepGuide`，`renderers.js:1596`）：

```
┌─────────────────────────────────────────────────────┐
│  处理进度                                             │
│  当前进度与下一步                                      │
│                                                       │
│  ●━━━●━━━●━━━○━━━○                                  │
│  ✓    ✓    ✓    4     5                              │
│  归档  提取  模板  生成   审核                         │
│                                                       │
│  👉 下一步：选择更新模板，告知平台这份材料的用途         │
└─────────────────────────────────────────────────────┘
```

### 5 个步骤

| 步骤 | 名称 | 触发条件 | UI 反馈 |
|------|------|---------|---------|
| 1 | 材料归档 | 文件上传完成 | ✓ 自动完成 |
| 2 | 内容提取 | 证据块提取完成 | ✓ 自动完成 |
| 3 | 选择更新模板 | 用户选择模板 | 用户操作 |
| 4 | 生成更新建议 | 点击「生成项目更新建议」 | 用户触发 |
| 5 | 审核发布 | 前往审核中心 | 引导跳转 |

### 步骤间的引导文案

- **Step 0**（处理中）：`⏳ 正在提取内容，请稍候…`
- **Step 1**（已就绪，未选模板）：`👉 下一步：选择更新模板，告知平台这份材料的用途`
- **Step 2**（已选模板，就绪可生成）：显示「👉 生成项目更新建议」按钮
  - 如果 `readiness.status === "blocked"`：`⛔ 内容完整性不足，需补充关键信息后才能生成建议`
- **Step 3+**（已生成建议）：显示「👉 前往审核与发布」链接

### 证据内容区

引导器下方是证据块索引 + 预览的双栏布局：
- **左侧索引**：证据块列表（类型 + 摘要 + ID）
- **右侧预览**：选中证据块的全文内容，可展开查看提取文本

### 审核操作

每条变更项（change）可以：
1. **接受**（accept）— 直接采纳 LLM 建议
2. **编辑后接受**（edit then accept）— 弹出编辑面板（`openReviewEditor`，`renderers.js:1814`），逐字段修改后再接受
3. **拒绝**（reject）— 不采纳，需填写原因

所有变更项审核完毕后，才能进入合并→发布流程。

### 发布检查清单（4 项必须全部通过）

| 检查项 | 含义 |
|--------|------|
| 草稿结构校验 | 草稿 graph 通过 `validateModuleGraph` |
| 存在待发布差异 | 草稿与发布版之间有变更 |
| 没有未决定审核项 | 所有提案的变更项都已 accept/reject |
| 提案不能直达发布 | 不存在提案直接合并到 published 的路径 |

### 发布流程

1. 输入版本标签（如 `v1.1.0`，字母数字开头）
2. 勾选确认「我已核对草稿差异、结构校验和待审核项」
3. 点「发布当前项目版本」
4. 发布成功 → Toast 提示 → 刷新页面

### 回滚

- 仅可回滚到**直接上一发布版本**（不支持多版本回退）
- 回滚后会创建新的草稿基线

## 16. SPA 路由机制

**代码**：`renderRoute()` — `app.js:1611`

平台使用 **History API** 路由（非 hash 路由），核心路由表：

| URL 模式 | 渲染函数 | 说明 |
|----------|---------|------|
| `/login` | `renderLogin()` | 登录页 |
| `/account/password` | `renderPasswordReset()` | 修改密码（首次登录强制） |
| `/projects` | `renderProjects()` | 项目列表 |
| `/projects/:id` | `renderProject(id, "overview")` | 项目总览 |
| `/projects/:id/modules/:type` | `renderProject(id, type)` | 模块页 |
| `/projects/:id/modules/materials/:materialId` | `renderProject(id, "materials", materialId)` | 材料详情 |
| `/projects/:id/modules/materials/generation-tasks/:taskId` | `renderProject(id, "materials", "", {generationTaskId})` | 生成任务详情 |
| `/projects/:id/modules/materials/proposals/:proposalId` | `renderProject(id, "materials", "", {proposalId})` | 提案详情 |

- `popstate` 事件监听浏览器前进/后退（`app.js:1686`）
- 未匹配任何路由 → 跳转到 `/projects`
- 未登录访问受保护页面 → 记录 `intendedPath`，跳转到 `/login`，登录后恢复
