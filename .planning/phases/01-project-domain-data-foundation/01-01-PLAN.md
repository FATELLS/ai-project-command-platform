# Plan 01: SQLite and Domain Foundation

## Objective

Create the runtime, migration, schema, transaction, and deterministic project-model validation foundation required by all later Phase 1 work.

## Must-haves

- Node.js runtime requirement explicitly supports built-in `node:sqlite` without flags.
- Fresh and repeated migrations are deterministic and checksum-verified.
- SQLite foreign keys, WAL, and busy timeout are configured.
- Projects, templates, users, memberships, versions, modules, units, stages, closures, tasks, task links, workstreams, workstream tasks, and proposal metadata are independent entities.
- Published and draft versions are separate rows; proposals cannot masquerade as either layer.
- Validator rejects duplicate IDs, missing/cross-unit/self dependencies, invalid parents, and cycles.

## Tasks

### 1. Runtime and scripts

- Raise `engines.node` to the selected Node 24.15+ floor.
- Add test, migrate, import, export, start, and verify scripts without third-party runtime dependencies.
- Keep the runtime database under `PLATFORM_DATA_DIR` or the ignored `data/` directory.

### 2. Database adapter and migration runner

- Implement one narrow `node:sqlite` adapter that opens/closes databases and exposes safe transactions.
- Set `PRAGMA foreign_keys = ON`, `journal_mode = WAL`, and a bounded busy timeout.
- Implement ordered SQL migrations with a `schema_migrations` checksum ledger.
- Reject a changed migration after it has been applied.

### 3. Initial schema

- Create the normalized tables from `RESEARCH.md` using STRICT tables, foreign keys, indexes, and uniqueness constraints.
- Give every version-owned entity an explicit position for stable export ordering.
- Store promoted relational fields in columns; allow entity-scoped JSON only for remaining display metadata.
- Ensure project version pointers can only target versions owned by the same project via repository validation.

### 4. Project model validator

- Validate fixture top level and published/draft snapshots.
- Validate stable IDs and unit/task/workstream relationships.
- Detect cycles across both parent and dependency edges.
- Return deterministic, actionable errors without writing data.

### 5. Tests

- Test fresh migration, repeat migration, checksum mismatch, pragma configuration, table/index presence, and transaction rollback.
- Test valid Xugu snapshots and synthetic invalid dependency/cycle cases.
