# 系统 SPEC：AI 项目作战管理平台

状态：`canonical`
版本：`1.0.0`

## 1. Mission

平台管理多个项目和团队，把路线、任务、材料、证据与项目更新统一为受控数据流程。AI 的价值是把材料转换成有来源的结构化建议，而不是生成页面或代替人员发布。

## 2. 角色

| 角色 | 能力 |
|---|---|
| 平台管理员 | 平台配置、用户、全部项目、AI 与运维 |
| 项目管理员 | 成员、材料、审核、发布和回滚 |
| 项目编辑 | 材料维护、生成和允许的审核操作 |
| 查看者 | 读取授权项目发布态和允许的问答 |
| LLM Provider | 受限生成建议或回答，不是受信任主体 |
| 材料 Worker | 在项目隔离与租约约束下产生证据 |

## 3. 核心对象

- `Project`：稳定项目身份、模板和版本指针。
- `ProjectVersion`：不可变发布或草稿快照。
- `ProjectCard`：任务、单元、阶段、成果、风险、指标等统一元素。
- `ProjectCardLink`：父子、依赖和其他显式关系。
- `Material` / `EvidenceBlock`：项目材料及可引用证据。
- `GenerationJob`：锁定材料、证据、模板和基准版本的生成任务。
- `ChangeProposal`：只含白名单结构化变更与证据引用。
- `ReviewItem` / `ReleaseEvent` / `AuditEvent`：审核、发布与追溯。

## 4. 不可违反的边界

1. 虚谷是唯一数据库和跨模块事务真相。
2. 项目图只读写 `project_cards` 与 `project_card_links`。
3. 所有项目业务对象必须携带并校验 `projectId`。
4. AI 不得写 `draft` 或 `published`，不得审核或发布。
5. 提案必须绑定 `baseVersionId`、模板版本、材料集合和证据集合。
6. 合并只写新的 draft 快照；发布只推进已审核版本指针；回滚只指向直接前驱。
7. API Key 不进入客户端、日志、导出、诊断或测试报告。
8. 发布包不携带项目数据、材料、运行卷或真实凭据。

## 5. 功能验收

- 多项目创建、切换、成员授权和越权隐藏。
- 总览、路线图、作战单元、甘特、健康和资料工作区可用。
- 材料创建/上传、提取、readiness、证据检索和问答可用。
- 材料可生成提案，逐项审核后合并、发布并回滚。
- `xugu-agentic-group` 导入导出语义等价：7 单元、29 任务、6 阶段及关系不丢失。
- managed 模式可一组命令启动和停止应用与专用虚谷。
- 冷备份可校验并恢复，恢复前保留当前 volume 副本。
- 桌面、平板和手机核心流程无阻断、无重叠、无控制台错误。

## 6. 非功能验收

- Node.js 20，ARM64 原生驱动，UTF-8 全链路。
- 参数化 SQL、显式事务、外键和应用层图校验共同保护数据。
- 登录、CSRF、会话、密码哈希、角色和项目隔离有自动化覆盖。
- Provider 使用 HTTPS 与主机白名单；日志和设置响应脱敏。
- 首次虚谷冷启动允许最长 420 秒，应用健康检查在迁移完成后才成功。
- 完整验证必须使用隔离虚谷容器、端口、volume 和真实 Chromium。
