# Plan 02: Project Repository and Xugu Migration

## Objective

Implement project-scoped repositories plus an atomic, idempotent importer and semantically lossless exporter for the sanitized Xugu v4.2 fixture.

## Must-haves

- `xugu-agentic-group` is the stable project ID and uses `campaign-map-v1`.
- Published and draft content are imported into two separate version graphs.
- Import is one transaction and leaves no partial project on failure.
- Repeating an identical import is a no-op; conflicting reuse of the same project ID fails explicitly.
- Export reconstructs the legacy fixture's published/draft semantics without losing IDs, order, null/empty-string distinctions, dependencies, stages, closures, or workstreams.
- Every repository lookup is scoped by `projectId`.

## Tasks

### 1. Project repository

- Implement project list/lookup and published/draft version resolution.
- Implement version-owned entity inserts and reads using prepared statements.
- Never resolve a version by version ID alone in a public repository method.
- Map normalized rows back to the legacy public snapshot shape needed for compatibility.

### 2. Legacy importer/exporter

- Validate before write, then insert template, project, versions, entities, and relationship rows within one transaction.
- Persist source ordering and entity display metadata.
- Attach version pointers only after the complete graph is present.
- Canonicalize and compare an existing imported project for idempotency.
- Export `{ published, materials: [], draft }` deterministically.

### 3. CLI entry points

- Provide explicit database path/data directory and fixture path arguments.
- Default only to the committed Xugu fixture and ignored runtime data directory.
- Print a concise integrity report with project/version/unit/task/stage/closure/workstream counts.
- Never read API keys, uploads, processed materials, or the reference runtime `state.json`.

### 4. Integration tests

- Assert expected Xugu counts in both layers.
- Assert stable group/task IDs, parent/dependency links, project version pointers, and template metadata.
- Assert semantic export equality against the committed fixture.
- Assert rollback on invalid fixture, repeat import behavior, and conflict rejection.
- Assert a second synthetic project cannot leak through project-scoped reads.
