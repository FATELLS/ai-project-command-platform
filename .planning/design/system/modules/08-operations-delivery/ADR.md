# ADR S-08：本地可观测、可恢复和无数据默认交付

状态：`accepted / implemented`
关联：D-001、D-018、D-020、D-027–029、D-043

## Context

内部生产试用需要在单服务器上排障、备份、恢复和发布安装包，同时必须避免把材料、密钥、数据库或提示词带入日志和分发物。

## Decision

- 每个 HTTP 和关键后台动作具有 requestId/trace。
- 未知错误保存脱敏事件、指纹和关联上下文。
- 诊断包只向授权管理员开放。
- 产品内提供确定性核心自检，不执行任意测试命令。
- 备份使用一致 SQLite 快照，恢复离线验证。
- 安装包采用运行白名单并默认空数据。
- 源码部署提供受控后台进程管理，但不接管外部数据库服务。
- Xugu 迁移使用脱敏 fixture，参考稳定应用保持只读。

## Rejected Alternatives

| 方案 | 原因 |
|---|---|
| 日志完整记录请求和 prompt | 会泄露密钥、材料和用户数据。 |
| 用户上传任意诊断脚本 | 形成代码执行入口。 |
| 发布包携带开发数据库 | 泄露真实项目和运行状态。 |
| 在线覆盖恢复 | 破坏活动连接和事务。 |
| 一个停止命令关闭平台与数据库容器 | 所有权不清，可能中断其他依赖数据库的系统。 |

## Consequences

- 诊断信息可能不足以复现材料正文问题，需要通过受控 requestId 和本地授权排查。
- 打包脚本必须维护白名单和敏感文件断言。
- 运维功能本身也受 project role 和审计保护。

## Invariants

- Cookie、CSRF、API Key、材料正文和模型提示词不得进入诊断包。
- Release 不包含 fixtures、测试、规划、数据库、上传或密钥。
- 参考 Xugu 来源未经明确迁移工作不得修改。
