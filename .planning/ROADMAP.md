# 项目路线图

状态：`accepted`

## Phase 1：项目域与数据底座

状态：`complete` （2026-07-18）

目标：建立可运行的平台骨架、SQLite Schema、项目仓储、版本模型和虚谷项目迁移器。

交付：

- 项目、作战单元、模块、版本、模板和用户基础模型；
- `published / draft / proposal` 三层状态；
- SQLite 初始化、迁移和事务；
- `xugu-agentic-group` 夹具导入与完整性报告；
- 项目级 API 命名空间和旧入口兼容策略；
- 自动化单元与集成测试。

验收：虚谷夹具可进入数据库并按项目 ID 返回 7 个作战单元、29 项任务及完整路线，不修改旧项目。

## Phase 2：平台壳、项目检索与切换

状态：`complete` （2026-07-18）

目标：实现登录后的平台首页和项目级导航。

交付：

- 项目列表、搜索、筛选、最近访问；
- 项目创建、编辑、归档和恢复；
- 项目切换器和项目详情壳；
- 当前虚谷项目通过新 URL 访问；
- 基础角色与会话。

验收：同一用户可在至少两个测试项目之间切换，数据和 URL 不串项目。

## Phase 3：模块注册表与项目模板

状态：`complete` （2026-07-18）

目标：把页面从项目硬编码改造成固定模块 + 数据配置。

交付：

- 九类基础模块 Schema 与渲染器；
- `campaign-map-v1` 和标准项目模板；
- 项目术语、主题、模块启停和排序；
- 路线、甘特、任务网络的通用数据接口；
- 虚谷视觉回归验证。

验收：不用改页面代码即可创建第二个不同名称、不同作战单元的项目并完整展示。

## Phase 4：项目材料与证据层

状态：`complete` （2026-07-18）

目标：将多样文件变成项目隔离、可引用的证据。

交付：

- 项目级上传、预处理和材料台账；
- 页、段、表和图片来源定位；
- 更新模板选择；
- 项目容量、并发、重复和文件门阀；
- 项目内只读问答迁移。

验收：两项目上传同名材料仍保持隔离，问答和证据检索不串库。

## Phase 5：LLM 结构化变更提案

状态：`next`

目标：从材料生成可校验的项目增量，而不是自由文本或页面代码。

交付：

- 会议纪要、计划、进度、指标、成果和新项目六类更新模板；
- `ChangeProposal` Schema；
- 来源、语义类型、置信度和警告；
- 任务依赖、日期、重复、证据和版本冲突校验；
- 生成任务、重试、Token 与成本监控。

验收：参考材料可以生成稳定 JSON；无证据完成状态、循环依赖和跨项目引用全部被拒绝。

## Phase 6：差异审核、发布、权限与运营

目标：完成低代码更新闭环并达到内部生产试用标准。

交付：

- 按模块差异审核、单项接受/驳回/编辑；
- 草稿预览、事务合并、发布和回滚；
- 完整角色权限与审计；
- 备份恢复、项目导入导出；
- 参考数据集、质量评估和跨项目安全测试；
- 虚谷项目迁移 UAT。

验收：管理员仅通过上传材料和审核提案即可推进虚谷项目路线与甘特，无需修改代码；发布和回滚可审计。
