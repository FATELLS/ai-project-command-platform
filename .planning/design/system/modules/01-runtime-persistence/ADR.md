# ADR S-01：单进程模块化单体与 SQLite 事务核心

状态：`accepted / implemented`
关联：D-005、D-007、D-008、D-018、D-027、D-029、D-043

## Context

首版面向本机或局域网单服务器部署，需要简单安装、强事务、项目隔离和可恢复发布。系统同时包含 HTTP、后台材料任务和版本图写入，但当前规模不需要分布式基础设施。

## Decision

- 使用 Node.js 单进程模块化单体。
- SQLite 是系统记录真相和跨模块事务边界。
- Web 与一个串行材料 worker 共享数据库。
- 平台进程的启动和停止与外部数据库服务生命周期分离。
- Schema 只通过顺序、带 checksum 的迁移演进。
- 运行备份使用 `VACUUM INTO`，恢复必须离线验证后替换。
- 发布包自带运行时，默认空数据启动。

## Rejected Alternatives

| 方案 | 原因 |
|---|---|
| 微服务 + 消息队列 | 增加部署、事务和排障复杂度，当前无规模收益。 |
| 单巨型 JSON 项目文件 | 难以保持关系、隔离、增量、事务和审计。 |
| 直接复制 WAL 数据库 | 可能得到不一致备份。 |
| 多 worker 直接并发 | 当前没有跨进程租约和写冲突证明。 |
| 停止平台时同时停止数据库容器 | 外部数据库可能被其他服务共享，平台只拥有自己的连接，不拥有数据库进程。 |

## Consequences

- 长任务必须异步化且有界，不能阻塞 HTTP 事件循环。
- 所有写路径必须明确事务边界。
- 扩展到多进程/PostgreSQL 前必须新增 ADR，不得仅替换驱动。

## Invariants

- 数据库是结构化真相，材料原件存储不替代数据库元数据。
- 启动迁移失败时服务不得继续。
- 恢复不得在线覆盖正在使用的数据库。
- 优雅停止不得跳过 worker 收尾或数据库连接释放；进程管理器不得调用外部数据库启停命令。
