# ADR S-03：固定模块、版本化项目图与模板化表达

状态：`accepted / implemented`
关联：D-003、D-010–013、D-019、D-021–026

## Context

平台必须支持不同项目语言和结构，又不能让项目数据或 LLM 注入页面代码。路线、任务、甘特、依赖和团队视图还必须读取同一事实版本。

## Decision

- 系统只注册九类固定安全模块。
- 模板版本不可变，定义术语、主题、字段、状态、必需模块和受控 view variant。
- 项目内容保存为版本化关系图，不保存任意页面 JSON/代码。
- 六个用户工作区只是九模块的信息架构分组。
- 路线图、卡片板、单元、依赖和甘特是同一版本图的投影。
- 作战单元生命周期、任务依赖和分形生命周期由领域校验和确定性派生保护。

## Rejected Alternatives

| 方案 | 原因 |
|---|---|
| LLM 生成页面代码 | 安全、维护和审计不可接受。 |
| 每项目独立 React/HTML 页面 | 内容更新重新变成定制开发。 |
| 各视图保存独立任务数据 | 会产生路线、甘特和看板不一致。 |
| 物理删除单元/任务历史 | 破坏版本和证据链。 |

## Consequences

- 新模块类型需要代码、Schema、loader、renderer 和模板目录共同发布。
- 项目差异只能通过数据、术语、主题和 allowlist 视图表达。
- 版本图写入必须经过完整校验。

## Invariants

- 未知 module/schema/view 失败关闭。
- 配置不能提供组件路径、HTML、CSS、JS 或 SVG。
- 路线图卡宽不伪装甘特工期。
- 单元退出和归档不删除历史事实。
