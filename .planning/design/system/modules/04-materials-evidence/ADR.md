# ADR S-04：项目隔离的有界材料流水线与代际证据

状态：`accepted / implemented`
关联：D-014、D-019、D-027、D-031、D-044

## Context

输入文件格式多样且不可信，提取工具能力不一致。证据既要支持问答和生成，又要在材料重处理后保持审计清晰，不能把旧片段静默当成当前内容。

## Decision

- 材料必须先归属项目，再进入任何处理。
- 原件存本地对象目录，数据库保存元数据、摘要和状态。
- 上传前执行容量、类型、魔数、重复、频率、并发和压缩门阀。
- 提取结果按 generation/version 保存，只有 active generation 进入当前检索和生成。
- worker 串行处理并保存稳定 job 状态。
- readiness 在模板选择后确定性计算并保存快照。
- UI 不暴露手动问答/生成授权，但底层隔离和可用性状态保留。
- 项目创建与项目更新共享文件声明/签名校验语义；创建文本还必须包含明确项目名称与目标。
- 所有材料输入或更新发起入口共享一份可下载模板目录；模板下载不得创建材料或改变项目状态。

## Rejected Alternatives

| 方案 | 原因 |
|---|---|
| 浏览器直接解析文件 | 难以统一安全门阀和审计。 |
| 覆盖旧证据块 | 破坏既有生成任务的来源解释。 |
| 所有文件交给 LLM | 成本、隐私、稳定性和格式定位不可控。 |
| 上传成功即允许生成 | 可能缺关键字段或尚未完成提取。 |

## Consequences

- 每个生成任务必须锁定证据 generation 和 hash。
- extractor 可以替换，但输出必须符合统一证据契约。
- 文件原件和预处理产物不进入 Git。

## Invariants

- 证据查询必须带 projectId。
- blocked readiness 不调用 generation provider。
- 处理失败不产生 ready/current evidence。
- archive/exit 等高影响建议必须有证据。
- 输入门阀失败不增加项目、材料或生成任务数量。
