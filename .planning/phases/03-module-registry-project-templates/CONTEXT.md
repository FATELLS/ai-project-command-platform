# Phase 3 Context: 模块注册表与项目模板

状态：`accepted for planning`
日期：2026-07-18

## 阶段目标

在不执行项目代码、不改变发布流程边界的前提下，把当前项目概览壳扩展为九类固定模块，并由版本化模板决定术语、主题、模块启停、顺序和固定视图变体。

## 锁定方向

- 桌面界面继续以 Xugu Agentic Group Schedule 为视觉基线，不恢复深色侧栏式 SaaS 壳。
- `xugu-agentic-group` 是首个作战项目，稳定 ID、v4.2 事实、路线、任务、甘特与成果语义不得丢失。
- Banner、标题、状态、事实标签和模块文案由项目模板与术语配置驱动。
- 首版模板为 `campaign-map-v1@1.0.0` 与 `standard-project-v1@1.0.0`。
- 九类模块只映射仓库内固定 renderer；数据库、项目数据和未来 AI 输出不得提供组件路径、HTML、CSS 或 JavaScript。
- `published` 与 `draft` 继续独立；Phase 3 的模块启停与排序管理只允许写 draft，不提前实现发布。
- 所有模块 API 和数据加载必须先按 `projectId` 与角色授权，再解析同一项目版本。

## 规划取舍

- Phase 3 建立最小规范化风险、指标实体和固定空状态，以满足九类模块契约；材料实体与上传仍留在 Phase 4。
- Phase 3 交付 draft-only 的模块启停/排序服务与管理界面；`overview` 必填且不可禁用，禁用模块不得删除事实数据。
- 路线、任务网络和甘特共享同一版本图的数据源，不在模块 JSON 中复制任务或路线事实。
- 标准项目必须使用数据驱动的线性路线、依赖列表/网络和泳道甘特；布局不得依赖 Xugu 固定的六节点、七单元或日期范围。

## 明确不做

- 材料上传、证据块和问答；
- LLM 提案生成；
- 提案审核、合并、发布与回滚；
- 任意自定义代码模块或拖拽网页生成器。
