# Plan 07-03：请求追踪、错误事件与诊断包

1. Add a request context layer in `src/http/app.mjs` that accepts or generates `requestId`, writes it to every JSON response and response header, and attaches it to audit metadata.
2. Add normalized `error_events` and `operation_traces` tables in migration 007.
   - Store requestId/traceId, route, method, status, userId, projectId, action, related material/job/proposal/release IDs, error code, stack fingerprint, redacted stack, createdAt.
   - Cap stack size and redact Cookie, CSRF, Authorization, API keys, material body, provider prompts and evidence text.
3. Wrap background material processing and generation attempts with trace IDs; persist failures even when no HTTP request is active.
4. Add admin-only diagnostics APIs for listing error events, viewing one event and exporting a diagnostic bundle.
5. Add a browser diagnostics panel with search by requestId/jobId/proposalId and copyable report text.
6. Add tests that force unknown HTTP errors, known domain errors, material processing failures and provider failures; verify response requestId, stored redacted stack and authorization boundaries.
