# 平台前端 UI 用户操作流程

本文档描述当前平台真实可操作的 UI 流程。项目资料与项目更新是两个相邻但独立的工作空间：

- 项目资料负责上传、归档、提取、模板选择和生成任务。
- 项目更新负责在正式路线图上下文中核对一次 AI 生成的节点变化。
- AI 预览不会直接修改草稿或发布版本；审核、合并和发布仍是独立动作。

## 1. 全局信息架构

项目内固定有六个内容工作区：

1. 作战总览
2. 项目路线图
3. 作战单元
4. 排期甘特
5. 项目健康
6. 项目资料

`项目更新` 是从材料到审核的流程入口，不是第七个内容模块。进入该流程时，六个模块标签均不显示选中状态，避免把更新错误理解为项目资料的一个页签。

项目资料只保留两个二级入口：

| 入口 | 路由 | 责任 |
|---|---|---|
| 战果档案 | `/projects/:id/modules/outcomes` | 查看成果与闭环记录 |
| 项目材料 | `/projects/:id/modules/materials?view=ledger` | 上传、录入、提取和管理材料 |

项目更新使用独立路由：

| 入口 | 路由 | 责任 |
|---|---|---|
| 项目更新 | `/projects/:id/updates` | 查看最近一次待审核更新的统一路线图 |
| 更新审核 | `/projects/:id/updates/proposals/:proposalId` | 逐项核对来源、字段和审核决定 |
| 审核与发布 | `/projects/:id/updates/release` | 检查草稿、发布或回滚 |

旧的 `materials?view=proposals` 与 `materials?view=release` 深链只做兼容重定向。

## 2. 项目创建

项目作战台支持：

- 手工创建项目。
- 下载项目创建材料模板。
- 上传项目材料后解析项目名称、目标和团队，进入项目骨架确认。

空文件、伪装格式、不支持格式以及缺少项目名称或目标的材料会原位报错，不创建半成品项目。

## 3. 项目总览

总览提供两个不同动作：

- `项目更新`：进入 `/updates`，核对已经生成的节点变化。
- `上传项目材料`：进入项目材料台账，开始新的材料归档。

这两个按钮不得合并。前者消费已生成的更新，后者生产新的材料输入。

## 4. 项目资料

项目材料台账支持文件上传和手工录入。上传面板与手工录入面板均可选择更新模板，也可下载对应模板。

材料处理流程：

1. 归档材料。
2. 提取可引用内容。
3. 选择更新模板。
4. 检查必要字段与生成就绪度。
5. 创建生成任务。

异常材料处理规则：

- 空文件、扩展名伪装和未知格式不得进入台账。
- 重复内容只保留一份，并在第二次上传时提示重复。
- 与所选模板不匹配的材料显示缺失字段，禁止生成。
- 生成失败保留任务记录；可重试失败允许重新执行，终止失败不创建预览。

生成任务成功后显示 `查看项目更新`，跳转到 `/projects/:id/updates`。

## 5. 项目更新

项目更新页只显示一张 `更新后的项目路线图`，不再显示以下重复内容：

- 生成控制台和批量生成按钮。
- 更新数量、处理中、失败和过期等统计卡片。
- 提案列表。
- 生成任务列表。
- 材料模板下载控件。

路线图直接复用主路线图的 `renderRoadmapSwimlane` 渲染器。输入数据是发布版本叠加当前更新后的内存投影，因此阶段、泳道、任务卡片、展开方式和待排期区与主路线图保持一致。

更新语义：

- `AI 新增`：蓝色高亮，只属于本次材料更新。
- `AI 修改`：橙色高亮，只属于本次材料更新。
- `当前节点 · 只读`：降低对比度，仅用于确认新卡片在正式路线中的位置。
- 没有日期或无法归入现有阶段的节点进入同一渲染器的 `待排期卡片` 区。

页面顶部只保留一条紧凑状态栏，显示基准版本、增删改数量、待确认数量和 `审核本次更新`。

## 6. 卡片编辑

主路线图和项目更新共用同一个卡片编辑器，但能力不同：

| 场景 | 可编辑范围 | 保存结果 |
|---|---|---|
| 主路线图 | 当前路线图中有权限的阶段和任务 | 创建新的待审核变更，不直接改发布版本 |
| 项目更新 | 仅本次更新标记为新增或修改的卡片 | 更新当前预览，重新计算路线图投影 |

编辑器支持字段增删改。删除卡片前必须在 `删除确认` 中完整输入 `确认删除`，按钮才可用。

项目更新中的只读背景卡片没有编辑按钮；服务端仍会对编辑和删除请求执行项目权限、proposal 状态和 changeId 校验。

## 7. 审核与发布

点击 `审核本次更新` 进入 proposal 详情：

1. 查看本次更新的来源材料与引用位置。
2. 查看每个变更的原值和建议值。
3. 接受、编辑后接受或拒绝每个变更。
4. 全部决定完成后合并到草稿。
5. 在 `/updates/release` 核对草稿差异并发布。

发布与回滚只对有权限的角色开放。所有状态变化都经服务端状态机和审计日志记录。

## 8. 核心点击路径

```text
项目作战台
  -> 项目总览
  -> 项目资料
  -> 项目材料
  -> 上传或手工录入
  -> 材料详情
  -> 生成节点预览
  -> 生成任务成功
  -> 查看项目更新
  -> 更新后的项目路线图
  -> 编辑本次高亮卡片或审核本次更新
  -> 合并草稿
  -> 审核与发布
```

## 9. 路由恢复

平台使用 History API。未登录访问受保护页面时会保存合法的项目、模块或更新流程路径，登录后恢复原位置。任何不符合路由白名单的 intended path 都会回退到 `/projects`。
