# 项目导航信息架构

状态：`accepted / implemented`

日期：2026-07-23

## 目标

项目导航按用户要完成的工作组织，而不是把九类底层技术模块全部平铺。导航收敛不得删除模块事实、破坏历史链接或改变发布、草稿、提案与权限边界。

## 一级工作区

| 一级入口 | 回答的问题 | 承载内容 |
|---|---|---|
| 作战/项目总览 | 项目现在是什么状态？ | 当前阶段、目标、摘要与事实计数 |
| 项目路线图 | 项目如何推进？ | 主任务时间线、阶段卡片板、作战单元进度、依赖网络 |
| 作战单元/团队 | 谁负责？ | 编组、负责人、目标、当前工作、预期产出与生命周期 |
| 排期甘特 | 时间如何安排？ | 真实起止日期、工期、负责人、进度与待排期任务 |
| 项目健康 | 是否偏离目标？ | 风险台账、效果指标 |
| 项目资料 | 有哪些成果和依据？ | 战果/交付物、材料台账、更新提案及其审核发布流程 |

## 合并规则

- Task Network 不再作为一级入口；Roadmap 的 `?view=network` 是用户侧统一依赖入口。
- Risks 与 Metrics 保持独立模块/API，但在“项目健康”内二级切换。
- Outcomes 与 Materials 保持独立模块/API，但在“项目资料”内组织；Materials 原有材料台账、问答、更新提案、审核发布和运维自检继续按角色显示。
- Gantt 不与路线图合并。路线图副任务卡只表达阶段归属，Gantt 才表达精确持续时间。
- Units 不与路线图合并。路线图表达推进，Units 表达组织责任、目标和生命周期。

## 兼容边界

- 服务端仍注册九类固定安全模块，模块配置仍管理完整九模块列表。
- 一级工作区只显示当前发布版中至少有一个已启用底层模块的分组。
- 原 `/modules/task-network`、`/modules/risks`、`/modules/metrics`、`/modules/outcomes` 和 `/modules/materials` 路由继续可访问。
- 不修改数据库 Schema、项目模板安全 allowlist、projectId 隔离、角色授权、CSRF、published/draft/proposal 或审核发布流程。

## 验收

- 桌面一级导航恰好显示六个工作区，不出现独立“任务网络”。
- 项目健康显示风险台账/效果指标二级导航。
- 项目资料显示战果档案/交付物、材料台账、更新提案二级导航。
- 当前一级和二级入口均有可见选中态，并支持左右方向键切换焦点。
- Xugu 与标准项目共享结构，但作战单元/团队、战果档案/交付物等术语继续由模板决定。
