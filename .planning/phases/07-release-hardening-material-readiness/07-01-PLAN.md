# Plan 07-01：材料关键内容覆盖与生成前诊断

1. Add a versioned readiness catalog for the six update templates.
   - Meeting notes: date/source, participants or owners, decisions, action items, responsible unit/person, due date when dates are being changed.
   - Project plan: goal, units, roadmap milestones, tasks, owners, dates, risks and metrics where present.
   - Progress report: as-of date, task/status/progress facts, blockers, next actions, owners and source.
   - Metrics data: metric name, value, unit, as-of date, target/source.
   - Outcome archive: outcome title, result, date, owner/source and linked stage/task when available.
   - New project material: project name, goal, initial units, roadmap, tasks, owners, risks and metrics.
2. Create a deterministic readiness service that reads extracted evidence blocks and returns `ready / warning / blocked`, missing critical fields, confidence-free rule evidence and suggested next materials.
3. Expose readiness in Materials and generation capabilities APIs before a generation task is created; blocked materials cannot start generation unless the selected template explicitly permits limited proposals.
4. Persist readiness snapshots with material generation jobs so reviewers can see what was known or missing at generation time.
5. Add tests for each template: ready material, warning material, blocked material, stale extraction, mixed templates and cross-project access.
