# 项目路线图

状态：`accepted`

## Phase 1：项目域与数据底座

状态：`complete` （2026-07-18）

目标：建立可运行的平台骨架、SQLite Schema、项目仓储、版本模型和虚谷项目迁移器。

交付：

- 项目、作战单元、模块、版本、模板和用户基础模型；
- `published / draft / proposal` 三层状态；
- SQLite 初始化、迁移和事务；
- `xugu-agentic-group` 夹具导入与完整性报告；
- 项目级 API 命名空间和旧入口兼容策略；
- 自动化单元与集成测试。

验收：虚谷夹具可进入数据库并按项目 ID 返回 7 个作战单元、29 项任务及完整路线，不修改旧项目。

## Phase 2：平台壳、项目检索与切换

状态：`complete` （2026-07-18）

目标：实现登录后的平台首页和项目级导航。

交付：

## Phase 4：项目材料与证据层

状态：`complete` （2026-07-18）

目标：将多样文件变成项目隔离、可引用的证据。

交付：

- 更新模板选择；

验收：两项目上传同名材料仍保持隔离，问答和证据检索不串库。

## Phase 7：材料更新可靠性、作战单元生命周期与发布运维

状态：`complete` （2026-07-20）

目标：把“上传材料即可更新项目”的能力从内部试用闭环提升为可发布、可排障、可自检的产品能力。

交付：

- 按更新模板检查材料关键内容覆盖，明确 `ready / warning / blocked` 和关键缺失原因；
- 支持作战单元/团队新增、归档、退出的结构化提案、审核、合并和发布；
- 归档/退出前校验未完成任务、依赖、甘特泳道、战线和证据引用，要求同步关闭、迁移或归档；
- 统一 request/trace ID、脱敏结构化错误事件、堆栈指纹、后台作业关联和管理员诊断包；
- 产品内管理员自检与回归用例中心，覆盖材料更新、关键缺失、作战单元生命周期、权限、发布和故障追踪；
- 浏览器 UAT 覆盖成功更新、缺失材料、单位退出、错误诊断和测试中心。

验收：用户上传符合模板要求的项目材料后，可生成包含任务和作战单元生命周期变化的可审核提案；材料关键内容缺失时产品明确标记并阻止或降级；任一 5xx 或后台失败都能用报障编号拉取脱敏堆栈和关联上下文；管理员可在产品内运行并查看核心回归测试。

## Phase 9：分形作战生命周期与拆解模型

状态：`in-progress` （2026-07-22 切片一 parentId 拆解链 + 切片二 LIF-01 术语模板化 + 切片三 LIF-04 多源收口已落地）

目标：把"分形作战生命周期 + 主副泳道双锚点 + 多次拆解合并"从 Phase 8 的纯投影可视化，深化为数据、提案与模板层的完整模型，让路线图同时表达战略、分工、推进与收口，且生命周期可下沉到作战单元。

背景：Phase 8 泳道视图（`?view=swimlane`）已落地范式可见层（三带、主副泳道、双锚点、并行子任务），但拆解关系靠任务→阶段窗口归属投影推断，缺真实拆解链；本阶段补齐数据与提案层。

交付：

- `parentId` 主→子任务真实拆解关系落到数据与提案层（schema 已支持），虚谷种子补真实拆解链；泳道视图从"任务→阶段窗口归属投影"升级为"显式拆解关系"。
- 阶段支持多次拆解（一个阶段多次向下分发子任务）与多源合并收口（多个子任务/单元汇入同一收口锚点），关系可追溯、可深链。
- 生命周期术语模板化（事前/事中/事后 vs PDCA / 客户自定义），随项目模板配置，切换模板后泳道术语随之变化。
- 作战单元副泳道内分形生命周期：单元内部表达自己的事前/事中/事后阶段动作。
- 收口锚点支持多对多（一个阶段多个收口、一个收口跨多阶段）。
- 浏览器 UAT 覆盖拆解下钻、收口回溯、单元级分形阶段、术语随模板变化与审核边界。

验收：泳道视图的主→副拆解与副→主收口有显式可追溯关系；作战单元副泳道能看到该单元自己的生命周期阶段；切换项目模板后生命周期术语随之改变；任一拆解/收口关系变更仍经提案审核，不直写 draft/published；既有 timeline/board/units/network/swimlane 视图与深链行为不回退。
