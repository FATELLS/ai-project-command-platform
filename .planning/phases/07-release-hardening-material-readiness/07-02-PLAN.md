# Plan 07-02：作战单元新增、归档与退出

1. Extend the versioned unit contract with lifecycle fields: `status` (`active`, `archived`, `exited`), `effectiveDate`, `lifecycleReason`, `owner` and evidence-backed source metadata.
2. Extend proposal templates and `change-proposal-v1` validation so unit lifecycle changes use `operation: "update"` with explicit lifecycle fields, not physical deletion.
3. Update generation prompts and validators so materials can propose:
   - new unit/team creation;
   - unit/team owner or objective updates;
   - archive/exit lifecycle changes;
   - required companion changes that move, close or archive open tasks.
4. Add graph validation for lifecycle transitions:
   - an inactive unit cannot keep active/open tasks unless the same proposal moves or closes them;
   - task dependencies, parent links, workstream links and Gantt lanes cannot point to inactive units in a misleading way;
   - exiting a unit requires effective date, reason and evidence;
   - historical published versions remain readable.
5. Update fixed renderers for Units, Task Network and Gantt to display inactive units as collapsed/marked in current views while preserving historical context.
6. Add review UI warnings for unit lifecycle changes, including impact count, affected tasks and blocked merge reasons.
